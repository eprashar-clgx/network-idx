Appendix · How raw features become scores
Fiber Potential Index v1 · rules frozen per run lightgbm_k8_v1
Step 1
Feature engineering
  • Missing / infinite values imputed by rule — e.g. cable_penetration → 0, fiber_opportunity_gap → 1.0, growth counts → 0; distances fill at a data-derived cap.
  • Convention: “missing = far / unserved = lowest opportunity” — null-filled distances sit at the cap, giving the lowest score.
  • Winsorize long tails — growth counts have a fat right tail, capped at the 99.5th percentile.
  • Domain bounds — proportion features clipped to [0, 1] (cable_penetration, fiber_opportunity_gap); raw unclipped value kept for monitoring.
Step 2
Scaling
  • Country-wide min–max to [0, 1] for scoring, so every feature shares a common range; frozen per run_id for reproducibility.
  • 5 features inverted (lower raw = higher opportunity): distance to nearest hotspot & fiber, cable penetration, top-tier fiber speed, provider competitive landscape.
  • Clustering scales differently — it uses z-scores (StandardScaler), not min–max, because that step compares feature shapes, not a bounded 0–100 score.
Step 3
Scoring
  • Sub-index (0–100) = within-bucket weighted sum of scaled features, rescaled 0–100 — telecom_index, pop_housing_index, growth_index.
  • Overall score (0–100) = weighted average of the three sub-indices:
    0.591·telecom + 0.240·pop_housing + 0.169·growth.
  • Weights come from the model (mean |SHAP|), not hand-picked — delivered as fiber_potential_index.
